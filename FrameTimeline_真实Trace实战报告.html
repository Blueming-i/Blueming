4. 前后帧证据

证据显示：异常从单个 18.105 ms 的 App Deadline Missed 开始，随后连续出现 Late Present / Buffer Stuffing。这个模式支持“应用自身首帧错过 deadline，后续出现缓冲呈现滞后”的描述，但不能单凭 FrameTimeline 证明具体是哪个锁、CPU 竞争、GPU fence 或 SurfaceFlinger 调度造成。

5. 线程与调度

CPU sched 数据存在，目标线程可以对齐到时间窗口。Running / Runnable 的区分应以 sched_slice 与线程状态联合判断。本报告不把 Running 时长直接等同于 CPU 根因，因为 GPU 表为空、线程锁等待和核竞争仍需更细的轨道证据。

6. SurfaceFlinger / DisplayFrame 边界

Actual rows 带有 display_frame_token，且 Launcher 异常行可与 DisplayFrame token 对齐。结构化 SurfaceFlinger layer/display 视图没有行，因此不能确认 HWC、Fence、DisplayHAL 或 SF 调度根因。

7. 证据链

用户操作窗口→Launcher layer #207→id 104732 App Deadline Missed→后续 Buffer Stuffing→线程 sched 可查→GPU/SF 根因待验证

8. 最终判断

已确认：目标窗口中发生 Launcher 侧卡顿信号。首个具名 Launcher 异常帧为 id 104732，present_type 为 Late Present，jank_type 为 App Deadline Missed，on_time_finish=0，layer 属于 com.android.launcher3 / upid 12。其后存在多帧 Buffer Stuffing / Late Present。

尚未确认：具体是 UI 主线程业务逻辑、RenderThread、锁等待、GPU、BufferQueue consumer、SurfaceFlinger 或 DisplayHAL 中哪一项造成 deadline miss。现有 trace 的 GPU 与 SurfaceFlinger 结构化表为空，不能越过证据边界。
